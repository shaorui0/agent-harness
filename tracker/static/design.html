Tracker：一个看板管住所有 session 的任务

按 workspace → session → 任务 三层展开。每个任务看三样东西：spec（要做什么）、status（session 现在在干什么）、summary（做完了哪些、还剩哪些，用 [x] / [ ] 显示）。

1 · 模型：四层，每层只有一个数据来源

Workspace一个仓库或目录（例如 infra）~/.claude/projects/<slug>/
→
Session一次 Claude Code 对话，可能跨几天<sid>.jsonl + sessions/*.json
→
Task（0..n 个）这个 session 推进的变更openspec/changes/<id>/
→
Spec · Status · Summary要做什么 · 现在怎样 · 剩什么tasks.md · session · claude -p
Session ↔ Task 是多对多

一个 session 可以推进好几个 change，一个 change 也可以跨好几个 session。两者靠「session 改过 openspec/changes/<id>/ 下的文件」自动关联，你不用手动绑定。

spec 用 OpenSpec 的产物

proposal.md 写为什么做、做什么，tasks.md 是带 - [ ] 的清单。清单本身就是进度，靠解析文件得到，不需要 LLM。

没有 spec 的 session

直接开干、没建 change 的工作也照样显示，只是没有任务清单，用「生成摘要」来补。想正式登记，就在那个 session 里跑 /harness-spec-backfill。

3 · 每个字段从哪来

看板上的东西来源怎么得到花不花钱
左侧 workspace → session 树~/.claude/projects/<slug>/*.jsonl按目录分组；进程活着看 ~/.claude/sessions/*.json，最近 6 小时内退出的也列出来免费
Status（在跑、在等你、结束、卡住）session 状态文件 + transcript 尾部增量读取，约 110ms 刷一次全量免费
Task 列表<ws>/openspec/changes/<id>/session 改过的文件（oplog 的 target、transcript 里的 Edit/Write）落在某个 change 目录下，就关联到这个 change免费
Task 的 [x] / [ ]tasks.md直接解析 checkbox；第一个 [ ] 标成「正在这条」免费
spec 详情（点开看）proposal.md / design.md原文渲染免费
diffgitsession 开始以后，在它改过的文件上统计 commit 数和行数，另加未提交的改动免费
Summaryclaude -p（haiku）只在你点按钮时生成，结果缓存起来；session 之后有新动静就标「已过期」一次约 1 次 haiku 调用
验收 gate（可选）.harness/scope/<slug>.yml与 change 同名的 scope 文件存在时，显示它的 review 状态免费

5 · 手动摘要：点一下，跑一次非交互的 claude

  1. 在看板上点 ↻ 生成摘要
  2. server 组装输入：session_recap.py 提取的 session 骨架 + 关联 change 的 tasks.md + git diff 统计
  3. 在一个隔离目录里执行 claude -p --model haiku --no-session-persistence，不进入交互，也不会作为新 session 出现在看板上
  4. 拿回 JSON：{done:[], remaining:[], blocked_on, diff_note}，渲染成 [x] / [ ]
  5. 结果按 transcript 修改时间缓存。session 之后又跑了几轮，看板就标「已过期，可重新生成」
输出约定（prompt 里写死，渲染端只认这几个字段）
done:       ["已完成并且有证据的事，每条一句"]
remaining:  ["说了要做、还没做的事"]
blocked_on: "在等谁或什么，没有就写 null"
diff_note:  "一句话说明改了哪些地方"

有 tasks.md 时，进度以它为准，summary 只是补充；没有 spec 的 session，summary 就是唯一的进度视图。原来那种「每条 prompt 自动调一次 LLM」的机制删掉。

6 · 日常怎么用：一条命令，其余都在 session 里做

你需要敲的

harness tracker          # 打开看板，就这一条

第一次用要先跑一次 bin/harness install，以后不用再碰。

在 session 里说一句话就行的

  • 「开个 change 做 X」→ /opsx:new，看板上出现新任务
  • 「继续」→ /opsx:apply 逐条打勾，看板进度跟着动
  • 「把这个 session 登记一下」→ /harness-spec-backfill
  • 「这个做完没」→ /harness-spec-review
场景操作
早上看昨晚还有什么没完打开看板，左侧树里黄点是在等你、红点是疑似卡住，右侧看 [ ]
回到一个停了几天的 session点「生成摘要」，看完点「复制 resume」，回终端粘贴，说「继续」
开了十几个窗口，不知道谁在等我顶栏「2 个 session 在等你」，点一下就只看这两个
某个 session 没走流程看板上它显示「无 spec」；需要的话在那个 session 里跑 backfill

7 · 给 AI 用：同一份数据，三种出口

JSON
GET /api/board
GET /api/board?ws=infra
POST /api/summary?sid=…
Markdown CLI
harness tracker show
harness tracker show infra

输出带 [x]/[ ] 的清单，agent 在 session 里直接跑就能看全局。

文件本身

tasks.md、scope、oplog 都是纯文本，agent 本来就能读。tracker 只是把它们汇总起来，没有另造一份数据。

8 · 砍掉或简化的东西

原来现在为什么
每条 prompt、每次状态变化都自动调一次 Haiku 提炼目标删掉，改成手动「生成摘要」spec 写在 tasks.md 里，不用猜；自动调用花钱，还会出现自己喂自己的循环
/task 命令（手动把 session 绑定到任务）不做session 改了哪个 change 的文件，就自动关联到哪个 change
/verify 命令（跑验收命令、记录 PASS/FAIL）不做，用 OpenSpec 自带的 /opsx:verify已经有了，不重复造
改 hooks 和状态栏，显示当前任务先不做看板已经够用，跑一周再看要不要
scope 的「review 后又改过」（drift）作为主指标降成详情页里的一行提示scope 写成宽目录时噪声很大；主进度改看 tasks.md
Tasks / Unscoped / Sessions 三个 tab合成一棵树，「无 spec」只是一个标记和你实际的心智一致：先看 workspace，再看 session
