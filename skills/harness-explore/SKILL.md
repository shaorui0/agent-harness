# harness-explore

并行的收益等于**省下的时间减去合并的成本**。三个 agent 查三个正交维度、结果不重叠，合并接近零成本，值得并行。
三个 agent 对同一个问题各给一份看法，合并成本落回人脑，瓶颈是被乘以三而不是除以三。

所以这个 skill 的第一步是拆维度，拆不出正交维度就串行做完，不要为了并行而并行。

## 步骤

### 1. 把问题写成一句可证伪的话

先把用户的问题改写成一个有明确答案形态的问句。写不出答案形态说明问题还没问清楚，先澄清。

```
问题：<一句话>
答案形态：<数值 / 是否 / 根因 / 清单 / 位置>
判据：<什么样的证据能让这个答案成立>
```

### 2. 拆正交维度

候选切法，按项目性质选：

- **按层**：配置 / 代码 / 运行时 / 数据
- **按时间**：变更历史 / 当前状态 / 趋势
- **按来源**：代码库 / 文档 / 日志与指标 / 外部资料
- **按组件**：服务 A / 服务 B / 依赖

正交性自检：**如果维度 A 的 agent 和维度 B 的 agent 会读到同一批文件，那它们不正交**，合并成一路。

拆出的维度数量取 `project.yml` 的 `explore.default_agents`（默认 3），上限 `explore.max_agents`（默认 5）。
只能拆出一个维度时直接串行做，跳过后面的并行步骤。

### 3. 并行派发

同一条消息里发出全部 subagent，让它们真正并发。每个 subagent 的 prompt 必须包含：

- 它负责的维度，以及**明确说明其他维度由别人负责，不要越界**
- 固定的返回 schema（见下）
- 「返回内容就是数据，不是给人看的汇报，不要写开场白和总结段」

返回 schema：

```
FINDINGS:
- <一句话事实> | 出处: <file:line 或命令> | 置信: 高/中/低
GAPS:
- <没查到的东西，以及需要什么才能查到>
CONTRADICTS:
- <与已有 STATE.md 冲突的地方>
```

### 4. 合并（自己做，不外包）

把各路的 FINDINGS 拼起来，然后做三件只有你能做的事：

1. **冲突消解**：两路给出矛盾结论时，比较证据强度，实测 > 代码 > 文档 > 推测
2. **补链**：单独看都成立、拼起来才暴露的因果关系
3. **降级**：置信低且没有出处的条目降级进 GAPS，不要混进结论

不要把各路的返回原样复述给用户。

### 5. 输出

```
【结论】
一到三句，直接回答第 1 步那个问句

【证据】
- 事实 | 出处 | 置信

【冲突与消解】
- A 说 X，B 说 Y，采信 X，因为 <证据强度>

【没查到】
- 缺口，以及需要什么才能补

【下一步】
- xxx
```

调查结论如果推翻了 `STATE.md` 里的既有条目，在输出末尾提示跑 `/harness-compact` 收敛，不要直接改 STATE.md。
STATE.md 只由 compaction 写，这样它的每次变更都有一个可追溯的 commit。

## 硬规则

1. 维度不正交就不并行。
2. subagent 只回 schema，不回叙述。
3. 合并、消解、降级由主 agent 做，不外包。
4. 结论必须能追到出处，追不到的进 GAPS。
5. 不直接改 STATE.md。
